# Assumptions and interpretations

The assignment (`Assignment-7-Details.md`) is authoritative. No professor clarifications were obtained, so where
the wording is ambiguous we made the conservative choices below. Each is a project decision, not an approved
interpretation. If a clarification arrives, update the affected requirement, code and tests together.

| ID | Assignment wording | What SilverFile does | Where |
|---|---|---|---|
| A-01 | "At least six distinct agents plus orchestration", but the agent table lists five functional agents plus the orchestrator | Six functional agents plus an orchestrator: the five named roles plus **Return Assembly & Provenance**, which owns the "every number has a source" gate and the official-form output. Seven roles do not need seven people. | `src/agents/return_assembly.py` |
| A-02 | Social Security worksheet "implemented for you", `tax_math` tools | No starter code was supplied. We built deterministic Decimal calculations and expose them through a real MCP server. They are not presented as professor-provided. | `src/tools/tax_calculations.py`, `mcp_server/server.py` |
| A-03 | "Grounded in the supplied reference corpus" | No corpus was supplied. We built a small cited rule registry from the assignment and verified pages of the IRS PDFs in `data/reference_tax_forms` (collected by the team with AI help; identity-checked in `data/source_manifest.json`). | `data/rule_registry.json`, `data/policy.md` |
| A-04 | §4.5 "processes 10 invoices sequentially in one thread" (and refers to a batch in §4.2 that does not exist) | Ten distinct 2025 **tax documents** (`bench_ten_docs`) read by the Document Extraction agent sequentially in one thread, in a fixed order, measured with the context strategy on and off. | `scripts/context_benchmark.py` |
| A-05 | Section cross-references (§4.3 for provenance, §4.5 for escalation) do not match the headings | Mapped by topic: provenance §4.2, accessibility §4.3, escalation §4.4, context §4.5. | all docs |
| A-06 | "Submitted" forms in the dashboard, yet the system must never file | "Submitted" means **submitted internally for human review**. That exact wording is used in the UI. Nothing is transmitted anywhere. | `src/state.py` `STATUS_LABELS` |
| A-07 | Output format of the "filled out form" not specified | The official 2025 Form 1040-SR PDF is filled (plus Schedule 1-A when line 13b > 0), stamped DRAFT, verified by read-back and by visible text on a flattened copy, alongside an interactive line-by-line provenance view and a JSON audit record. | `src/output/pdf_writer.py`, `src/ui/provenance_view.py` |
| A-08 | Extraction "will be tested on the submission of a W-2 form only" | W-2 images must be uploaded (typed W-2s are refused). 1099-INT/DIV/R and SSA-1099 can be uploaded as images or typed in by the taxpayer; typed forms are recorded as direct user input. | `src/agents/document_extraction.py` |
| A-09 | "Other values not listed above are just entered directly" | Schedule 1 line 10 and line 26 (plus line 21 for the Social Security worksheet), Schedule 2 lines 3 and 21, Schedule 3 lines 8 and 15, estimated payments, and line 19 (only if dependents are claimed) are direct inputs with provenance. Lines 1b-1i, 7a, 13a, 25c and 27a-30 are not used and are $0 or blank; anything that would need them escalates. | `src/agents/intake_script.py` |
| A-10 | "Every number comes from a deterministic MCP tool call" | All arithmetic, including adding document boxes and comparing stated and document amounts, runs in the MCP server. Agents only gather inputs and copy outputs. | `src/agents/computation.py` |
| A-11 | Line 16 source "Rate schedule", with qualified dividends in scope | Tax uses the 2025 Tax Table (TI < $100,000), the Tax Computation Worksheet (>= $100,000), and the Qualified Dividends and Capital Gain Tax Worksheet whenever line 3a > 0, so qualified dividends are never taxed as ordinary income. The tax function matches every row of the printed 2025 Tax Table. | `src/tools/tax_calculations.py` |
| A-12 | Rounding not specified | Whole-dollar rounding (IRS Instructions p. 23): cents kept while adding several amounts for one line, only the total rounded; worksheet intermediates kept exact, results rounded half-up. | `src/money.py` |
| A-13 | "Valid SSN" for the enhanced senior deduction | A fictional 900-series SSN counts as "valid" in this classroom system. The real rule needs an SSN valid for employment. | `src/agents/eligibility_rules.py` `compute_boxes` |
| A-14 | Lines 4a and 5a are "total" amounts | The IRS instructions say to leave 4a/5a blank when a distribution is fully taxable. We follow the assignment table and always fill 4a/5a with the gross amount. A preparer may blank them. | `src/agents/computation.py` |
| A-15 | 1099-R scope "(code 7 / QCD flag)" | Only distribution code 7 is supported. Any other code escalates. The QCD amount is a taxpayer answer (the 1099-R does not show it); the taxpayer must have been 70 1/2. Births after July 1, 1954 escalate for a human check, because the distribution date is unknown. | `eligibility_rules.py` |
| A-16 | 1099-DIV capital gain distributions | They need line 7a. Capital gains are out of scope, so any box 2a amount escalates. | `R-DIV-01` |
| A-17 | User/document conflict threshold not given | Material when the stated and document amounts differ by more than the larger of $1,000 or 10% of the document amount. The taxpayer gets one follow-up question, and the case escalates if that does not resolve it. Listing fewer forms than were uploaded also triggers a follow-up. | `R-CONFLICT-01` |
| A-18 | Filing-status validation depth | The taxpayer chooses the status; SilverFile checks it against a few facts (spouse died in 2025, QSS death year and dependent child, HOH qualifying person). Anything inconsistent or "not sure" escalates; SilverFile never picks a status. | `R-FS-01`, `R-FS-02` |
| A-19 | Minimum PII | SilverFile does not ask for a home address or bank account numbers (a preparer adds them at signing). It asks for SSNs only for the taxpayer, spouse and dependents because they go on the form. An SSN typed anywhere else is removed and not stored. A document showing a non-test SSN is rejected, its file deleted, and no digits kept. | `src/ssn.py`, `intake.py`, `document_extraction.py` |
| A-20 | Dependents | Name, test SSN and relationship are recorded and printed (up to four; more escalates). Credits for dependents (Schedule 8812) are not calculated; line 19 is a direct input. | `R-DEP-01` |
| A-21 | Orchestrator "may be involved with dashboard" | The orchestrator is deterministic code (not an LLM). Routing must be auditable and termination guaranteed. Model calls are used where judgement on unstructured input adds value: reading replies, reading images, scope screening, audit critique, explanations and the cover note. | `src/agents/orchestrator.py` |
| A-22 | Model provider | Anthropic API with `ANTHROPIC_MODEL` configurable (default `claude-opus-5-5`). Without a key, an offline mode uses OCR and rule-based parsing so the system and tests still run. Offline runs never report token usage. | `src/llm.py` |
| A-23 | Reviewer identity | No authentication in this local prototype. The reviewer types a name, which is recorded on every decision. Taxpayer and reviewer actions use separate service calls, so a taxpayer message can never resolve a review. | `src/service.py` |
| A-24 | Five-page report and demo video | Out of scope for this build at the team's request. The repository supplies the material they would draw on (README, implementation notes, metrics, acceptance results). | - |
